## 一、地圖：單線四關，通關給分裂

- 四關一條線（`MAP_STEP_YS` v3＝`[300, 216, 132, 48]`，四站均分面板）。
- 第 1 關維持**金／紅競速**：先完成合成的那色定本局的神（紅→⚡宙斯、金→👑赫拉），
  第 2～4 關才填上剩餘三色（隨機不重複）。這段與 v2 相同，共用 `isForkRule()`。
- **通關獎勵＝該色分裂**：地標名牌顯示「分裂 2×1」（SFG 中自動變「分裂 4×1」）。

### 分裂的唯一來源

| 情況 | 結果 |
|---|---|
| 合成的顏色＝目前這一關要的顏色 | 通關 ＋ 該色直接切到上限（NG／FG 2×1、SFG 4×1） |
| 合成的顏色**先前已通關**（`v3ColorCleared`） | 照樣分裂到上限 |
| 合成的顏色還沒輪到 | 只合成成 1×2，**不分裂** |
| 雙色進階合成（1×4） | **不給分裂**，只計入 JP 收集點 |

「已通關的色照樣分裂」這條是刻意的：地圖在 FG／SFG 跨局保留，通關數越多、可分裂的顏色越多，
FG 後段自然越強。若少了這條，FG 打到後面會完全沒有分裂可拿。

同一波連爆中同色連續合成好幾次時，一關只會被推進一次，因此**只有第一次給分裂**
（`v3ClearsNow` 會檢查待補判佇列裡是否已有一筆卡在同一關）。

## 二、SFG：一次切 3 刀

`maxSplitCap()` 在 SFG 回 4、其餘回 2。v3 的 `applySingleSynthesis` 是
`splitCount[colorId] = maxSplitCap()`（直接指派，不是 ++），所以 SFG 中通關當下就是 4×1，
不必像 v2 那樣多做幾次合成慢慢累積。分裂數在 SFG 跨局保留、NG／FG 每局歸零（沿用 v2）。

## 三、JP：石像旁的兩個羅盤

- 條件不變：**定神後的雙色進階合成 2 次**（`JP_NODES` 預設 2，調校面板可調 1～6）。
- 定神前（含定案當次）完成的進階合成不計入 —— 沿用 v2 的 `jpIslandSeq` 流水號比對。
- 呈現改為盤面上方兩尊石像的彩金牌下方，一次點亮一個羅盤，點滿即發該神 JP。
- `jpIslandOpen()` 只在 v2 為真；v2／v3 共用的「收集軌道已開」改問新的 **`jpTrackOpen()`**。
- 連爆結算前會等羅盤點亮演繹播完（`beaconAnim`），確保 JP 彩金在該局連爆完全結束後才給付。

## 四、盤面正上方的半圓指南針

- 位置 `LAYOUT.compass`：**框的下緣就是圓心**（＝盤面上緣），只畫上半圓，
  下半圓落在盤面裡的那一半整個裁掉不顯示。
- 未定案：指針在半圓範圍內來回擺。
- 定案：甩向本局的神並回穩（`compassAnim`，時長沿用 `TIMING.mapForkResolve`）——
  **紅→指左上（⚡宙斯）、金→指右上（👑赫拉）**，正好對著上方對應那尊石像。

## 五、盤面上方的宙斯／赫拉石像＋彩金牌

版位比照 Game_283 海克力士（企畫「主盤上方左右需有JP欄位：造型以及設計沿用 Game_283 海克力士」）。

**素材來源**：`Hercules/assets/jp_num_02.png`（1124×751 神殿框）裁下四塊，
拼成一張 392×159 的小圖以 base64 內嵌（`TOP_GODS_SHEET`，維持單檔 demo）：

| 區塊 | 神殿框內座標 | 尺寸 |
|---|---|---|
| 宙斯石像 | (0, 96) | 132×118 |
| 赫拉石像 | (994, 96) | 130×118 |
| 宙斯彩金牌 | (134, 148) | 196×41 |
| 赫拉彩金牌 | (794, 148) | 196×41 |

**沒有取的**：神殿框本體、柱子、山牆匾額（MYTHIC JACKPOT 是海克力士的字樣）、血條。

兩個實作重點：

1. **彩金牌要先蓋掉素材烙上的示意數字**（123,255,668）再畫本作彩金。
   凹槽座標 `TOP_GODS_GROOVE` 換算自 Hercules `drawJPBanner` 的同一組值。
2. **落選那尊的壓暗不能用 `globalAlpha`**：那會連凹槽底色一起變半透明，
   海克力士的示意數字就會透出來（實際踩過）。改成整組先畫進離屏圖層
   （`godLayerCtx`）再帶著透明度貼回畫面。

神名沒有用素材原本的 Zeus／Hera 緞帶——緞帶背後連著山牆斜板，裁進來是雜訊，
改由程式畫「⚡ 宙斯 JP／👑 赫拉 JP」。
