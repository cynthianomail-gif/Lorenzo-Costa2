# 多組得分改為一組一組依序框起

日期：2026-08-04
狀態：已實作

## 背景

一個盤面可能同時有兩組（含）以上不同圖示得分。原本的演繹是全部同時框起、同時顯示得分數字、同時消除，玩家看不出來自己是靠哪幾組拿到分數的。

企劃要求改成：先框第一組 → 再框第二組 → 顯示綜合得分數字 → 兩組一起消除。

## 演繹順序

以兩組為例：

| 階段 | 畫面 | 時長 |
|---|---|---|
| 1 | 第一組框起，其餘壓暗 | `winGroupStep` |
| 2 | 第一組維持亮著，第二組也框起 | `winGroupStep` |
| 3 | 兩組都亮，中央彈出綜合得分數字 | `comboPause`（現行） |
| 4 | 兩組一起消除 | 消除演繹（現行） |

框是**累積**的：框第二組時第一組不收掉。綜合數字出現時兩組都是亮的，接著一起消除。

**只有一組時完全不進這個流程**，直接照原本的節奏走，避免每次普通得分都被多拖 0.35 秒。

組的順序是 `winLines` 的順序，也就是 symId 由小到大。

## 實作

### 狀態機

新增 `STATE.WIN_GROUPS`（6），插在 `SYNTHESIS` 與 `SHOWING_WIN` 之間：

```
SYNTHESIS ─┬─ 1 組 ────────────────→ SHOWING_WIN → POPPING
           └─ 2 組以上 → WIN_GROUPS → SHOWING_WIN → POPPING
```

### 中獎格的標記時機

`calcWin()` 原本一算完就把所有中獎格設 `isMatched = true`。改成每組各自把座標收進 `winLines[i].cells`，先不標記：

```js
winLines.push({ symId, matchCount, ways, win: symWin, cells });
```

改由 `lightWinGroup(i)` 一組一組點亮。得分框、未得分壓暗、消除縮放全都是看 `isMatched`，所以不必各自改判斷，自然變成「亮到哪框到哪」。

合成格（1×2／1×4）的從格一併收進該組的 `cells`，維持原本「縮小動畫與粒子特效覆蓋整個合成格」的行為。

同一個合成格可能同時屬於兩組（它帶的顏色對應到兩個 symId），組與組的 `cells` 允許重疊，重複標記 `isMatched` 沒有副作用。

### 每組的入場力道（搖晃）

搖晃是**每一格自己的** `cell._winFx` 幀數倒數，不是全盤共用的計時器——框到哪一組，就只有那一組搖。`lightWinGroup()` 只對「這次新亮起來」的格子設 `_winFx`，已經屬於前面組別的格子（例如兩色合成格會同時屬於兩組）跳過不重設，所以第一組不會在第二組框起時又抖一次。

角度由 `winFxRot(cell)` 算出，單格與合成格共用同一個函式。合成格（1×2／1×4）用主格的 `_winFx`，繞**整塊**的中心旋轉，框跟著一起轉。

`_winFx` 在 `updateWinGroups()` 與 `updateShowingWin()` 每幀由 `tickWinFx()` 倒數，進入消除時一併清掉。

`winFxTier`（低／中／高）依**全部組別加總後**的得分計算，在進入 `WIN_GROUPS` 前就決定，所以每一組的框與搖晃都是同一階強度。

### 得分數字

`drawCenterWin()` 開頭是 `if (currentState !== STATE.SHOWING_WIN) return;`，不必改 —— `WIN_GROUPS` 期間本來就不會畫出數字，符合「框完才顯示綜合得分」。

## 節奏參數

新增 `TIMING.winGroupStep`，預設 **0.40 秒**，掛在調校面板「消除／得分」分組，甘特起點 0.00。

兩組就是比舊版多 0.8 秒才看到得分數字。

## 不動的部分

- 綜合得分數字的內容、`×N` 倍數打擊動畫
- 消除演繹與粒子特效
- 連爆（cascade）邏輯與 `comboCount`
- 合成／分裂、藏寶圖推進

## 驗證

實機轉出兩組得分的盤面，記錄狀態轉移：

| 情境 | 結果 |
|---|---|
| 2 組 | `WIN_GROUPS`(groupIdx 0，亮 6 格) → `SHOWING_WIN`(亮 11 格) → `POPPING`(11 格一起消除) |
| 1 組 | 直接 `SHOWING_WIN`(亮 4 格) → `POPPING`，不經過 `WIN_GROUPS` |

並比對「第一組點亮時的 `isMatched` 集合」與 `winLines[0].cells` 完全相同，確認沒有提前洩漏第二組。

搖晃另外用四組得分的盤面驗證：每次框起新的一組時，只有該組的格子 `_winFx` 非零，先前框好的組全是 0，確認不會重搖。合成格則以 1×2 盤面確認整塊一起傾斜，角度與同組單格相同。
