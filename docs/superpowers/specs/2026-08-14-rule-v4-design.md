# 規則 v4：五色角色列 ＋ FG 航海地圖

日期：2026-08-14
狀態：已實作（`RULE_VERSION = 4`，並設為預設版本）
來源：企劃 2026-08-13 口述的 v4 改動說明（NG／FREE GAME 兩段）。
※ v1／v2／v3 完全保留，可在調校面板「🗺️ 規則」分頁切回對照。

## 與 v3 的差異總表

| 項目 | v3 | v4 |
|---|---|---|
| 一般圖示 | 8 個（4 色 × 角色／武器） | **10 個**（新增紫色：阿塔蘭忒／弓） |
| 分裂來源 | 地圖通關 | **合成本身**：同色合成切一刀，進階合成切第二刀 |
| 分裂上限 | NG／FG 2×1、SFG 4×1 | **一律 3×1**（一刀＋進階第二刀） |
| NG 地圖 | 單線四關＋盤面倍數 | **整段移除**（無地圖、無倍數） |
| JP 條件 | 雙神各湊 2 組顏色組合 | **角色列**：一整列 5 隻角色相鄰，中間格定獎 |
| 彩金 | 無（只有兩尊神 JP） | **五階**：宙斯 JP／赫拉 JP／MAJOR／MINOR／MINI |
| FG 地圖 | 沿用 NG 的關卡地圖 | **新的航海地圖**：連爆推進，倍數階梯 |

## 一、圖示：新增第 5 色

`SYMBOLS` 由 10 筆變 12 筆。**id 配置有動**：

| id | 內容 |
|---|---|
| 0–7 | 紅／金／藍／綠 各 角色＋武器（不變） |
| **8, 9** | **阿塔蘭忒（char）／弓（weapon），紫 `#a855f7`，colorId 4** |
| **10, 11** | 船頭／船尾（原本是 8／9，**往後移了**） |

這樣排是為了保住 `colorId = Math.floor(id / 2)`、`id % 2 === 0 ⇒ 角色` 這兩條全檔到處在用的約定。
代價是原本寫死的 `id === 8`／`id === 9`／`id < 8` 全部要換掉，改用：

- `SC_BOW` / `SC_STERN`（＝10／11）
- `isScSymId(id)`、`isNormalSym(id)`（id 0..9）、`isCharSym(id)`
- `NORMAL_SYM_COUNT`（＝10）、`COLOR_COUNT`（＝5）、`newSplitArray()`

**踩過的坑**：第一輪掃描用 `id === 8` 之類的字面比對，漏掉了 `applyGravity()` 裡變數名為 `_gId` 的那一組
（`_gId >= 8`）。補牌路徑漏改的話，紫色圖示會被當成船頭船尾。改這類全域邊界時，
搜尋要用「`>= 8`／`=== 8`」而不是「`id >= 8`」。

**紫色只在 v4 出現**：靠 `activeColorCount()`（v4 回 5、其餘回 4）在 `symWeights()` 裡把
未啟用的色權重補 0。v1～v3 因此完全抽不到 id 8／9，四色行為原封不動。

## 二、分裂（刀）：一刀 ＋ 進階第二刀

| 事件 | 效果 |
|---|---|
| 同色（角色＋武器）相鄰合成 | 該色 `splitCount = 2`（切一刀）。**再合成幾次都還是 2** |
| 兩個相鄰 1×2 不同色 → 進階合成 1×4 | 兩色各 `splitCount = 3`（第二刀，上限） |
| 角色列 1×5 | **不給分裂**（企劃 2026-08-14 確認：純粹給分／發獎，不算一次合成） |

`V4_SPLIT_BASE = 2` / `V4_SPLIT_ADV = 3`，`maxSplitCap()` 在 v4 回 3。

上限壓在 3 是照企劃的終態數字回推的：五色全切滿時
`ways = (ROWS × 3)^COLS = 12^5 = 248,832`，與企劃書一致（放到 5 刀會變成 3,200,000）。
單元測試 `ways.248832` 就是在守這個數字。

保留規則沿用舊制：**NG 每局歸零，FG／SFG 內跨局保留，FG／SFG 結束才一併重置**。

## 三、取得 JP／彩金：角色列

**條件**：任一橫列的 5 格全是「未合成的角色圖示」，且 5 隻**各不相同**
（盤面 5 欄、v4 剛好 5 色 ⇒ 等於五隻角色排滿一整列）。

**定獎**：看該列**中間格（第 3 欄，`V4_CENTER_COL = 2`）**是誰。

| 中間格 | 獎項 |
|---|---|
| 海克力斯 | ⚡ 宙斯 JP |
| 伊阿宋 | 👑 赫拉 JP |
| 美狄亞 | MAJOR（75 × bet） |
| 奧菲斯 | MINOR（10 × bet） |
| 阿塔蘭忒 | MINI（5 × bet） |

**結算**：該整列合成為一個 **1×5 合成格**（`isHeroRow`），同時替代五色的角色與武器，
照現有 ways 規則計分；獎項排入 `heroRowPending`，等**本局連爆全部結束後**才發
（與 v3 的 JP 同一個時機，避免報獎蓋掉連爆演繹）。

角色列**不動 `splitCount`、也不寫進 `synthesizedColors`** —— 它是給分／發獎事件，
不是一次合成。分裂的來源只有一般合成（第一刀）與進階合成（第二刀）。

三個實作細節：

1. 偵測掛在 `STATE.SYNTHESIS` 的初始化，且排在一般合成掃描**之前**——
   否則那一列會先被當成一般合成候選。角色列不可能含船頭船尾，與船的偵測互不干擾。
2. 一次只處理由上往下第一個成立的列；合成後那一列不再是角色列，不會重複計。
3. 合成格「代表哪幾色」原本是 `[colorId, colorId2]` 硬組的，接不到 1×5。
   改成統一問 `mergeColorIds(cell)`（支援 `colorIds` 陣列）。

## 四、出牌規則

- **五色合成率相等**：五色同權重，角色 7／武器 12（NG 另加船頭船尾各 2）。
- **第 3 輪單獨配重**（`V4_REEL3_CHAR_W`）：第 3 輪正好是角色列的中位格，
  在該欄把角色權重改成 海克力斯 3／伊阿宋 4／美狄亞 7／奧菲斯 9／阿塔蘭忒 13，
  做出「宙斯 < 赫拉 < MAJOR < MINOR < MINI」的五階獎頻率階梯。
  其他四輪維持等權，所以「五色合成率相等」不受影響（合成看的是同列相鄰兩格，不是單一輪）。
- `randomSymId()` / `randomReelSymId()` / `randomNormalSymId()` 都多收一個 `col` 參數；
  補牌（`applyGravity`）與初始鋪盤都要把欄號傳進去，否則第 3 輪的配重不會生效。

## 五、NG：地圖整段移除

`hasMapQuest()`（＝`!isV4()`）是總開關，擋掉 `drawMapPanel` / `drawMapShip` / `drawTMAnim` /
`tryAdvanceQuest` / `requestQuestAdvance` 的入列。盤面倍數恆 1，得分公式維持
`押注額 × 賠率 × Ways`。

盤面改為置中放大：`V4_LAYOUT_NG` grid x310 y124、格子 132（660×528）。
y 不能再往上：上方石像組下緣在 y=120；下緣也不能超過 spin 按鈕（y≈658）。

石像（`drawGodStatues`）在 v4 保留——它是兩尊神 JP 的顯示位置——但牌子下方的
v3 收集羅盤換成「角色列中心＝海克力斯／伊阿宋」的條件提示（v4 沒有累積過程）。

## 六、FG 航海地圖

新機制，與 v1～v3 的關卡地圖無關（另一個函式 `drawV4Voyage`）。

- 每次連爆推進 1 站，倍數：×1（首次得分）→ ×2 → ×3 → ×4 → ×5 → ×10，**第 7 段起維持 ×10**。
- 本次得分用「推進前」的站別，給完分才推進（所以第 1 次得分確實是 ×1）。
- **FG 每局重置**回起點；**SFG 不重置**，跨局一路累積。
- JP 與角色列彩金**不**與這個倍數相乘。

版面：FG／SFG 時盤面收回 x195／格子 130，右側 x1010 讓出來畫航海地圖；
NG 再切回置中放大。由 `syncV4Layout()` 在 `update()` 每幀檢查，**只在模式真的切換時**套用一次
（每幀都套會蓋掉調校面板「佈局」分頁的手動拖動）。

**踩過的坑**：`applyRuleLayout()` 會直接覆寫 `LAYOUT.grid` 與 `CELL_SIZE`，
但沒清掉 `_v4LayoutMode`，於是「在 FG 中切換規則版本」之後 `syncV4Layout()` 會誤判
模式沒變、不再把 FG 版面補回來。修法是在 `applyRuleLayout()` 裡把 `_v4LayoutMode` 設回 null。
這個是截圖驗證時抓到的，單元測試沒守到。
