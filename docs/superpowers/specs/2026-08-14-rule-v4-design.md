## 一、圖示：新增第 5 色

`SYMBOLS` 由 10 筆變 12 筆。**id 配置有動**：

| id | 內容 |
|---|---|
| 0–7 | 紅／金／藍／綠 各 角色＋武器（不變） |
| **8, 9** | **阿塔蘭忒（char）／弓箭（weapon），綠 `#059669`，colorId 4** |
| **10, 11** | 船頭／船尾（原本是 8／9，**往後移了**） |

這樣排是為了保住 `colorId = Math.floor(id / 2)`、`id % 2 === 0 ⇒ 角色` 這兩條全檔到處在用的約定。
代價是原本寫死的 `id === 8`／`id === 9`／`id < 8` 全部要換掉，改用：

- `SC_BOW` / `SC_STERN`（＝10／11）
- `isScSymId(id)`、`isNormalSym(id)`（id 0..9）、`isCharSym(id)`
- `NORMAL_SYM_COUNT`（＝10）、`COLOR_COUNT`（＝5）、`newSplitArray()`

**踩過的坑**：第一輪掃描用 `id === 8` 之類的字面比對，漏掉了 `applyGravity()` 裡變數名為 `_gId` 的那一組
（`_gId >= 8`）。補牌路徑漏改的話，紫色圖示會被當成船頭船尾。改這類全域邊界時，
搜尋要用「`>= 8`／`=== 8`」而不是「`id >= 8`」。

**紫色只在 v4 出現**：靠 `activeColorCount()`（v4 回 5、其餘回 4）在 `symWeights()` 裡把
未啟用的色權重補 0。v1～v3 因此完全抽不到 id 8／9，四色行為原封不動。

## 二、分裂（刀）：一刀 ＋ 進階第二刀

| 事件 | 效果 |
|---|---|
| 同色（角色＋武器）相鄰合成 | 該色 `splitCount = 2`（切一刀）。**再合成幾次都還是 2** |
| 兩個相鄰 1×2 不同色 → 進階合成 1×4 | 兩色各 `splitCount = 3`（第二刀，上限） |
| 角色列 1×5 | **不給分裂**（企劃 2026-08-14 確認：純粹給分／發獎，不算一次合成） |

`V4_SPLIT_BASE = 2` / `V4_SPLIT_ADV = 3`，`maxSplitCap()` 在 v4 回 3。

上限壓在 3 是照企劃的終態數字回推的：五色全切滿時
`ways = (ROWS × 3)^COLS = 12^5 = 248,832`，與企劃書一致（放到 5 刀會變成 3,200,000）。
單元測試 `ways.248832` 就是在守這個數字。

保留規則沿用舊制：**NG 每局歸零，FG／SFG 內跨局保留，FG／SFG 結束才一併重置**。

## 三、取得 JP／彩金：角色列

**條件**：任一橫列的 5 格全是「未合成的角色圖示」，且 5 隻**各不相同**
（盤面 5 欄、v4 剛好 5 色 ⇒ 等於五隻角色排滿一整列）。

**定獎**：看該列**中間格（第 3 欄，`V4_CENTER_COL = 2`）**是誰。

| 中間格 | 獎項 |
|---|---|
| 海克力斯 | ⚡ 宙斯 JP |
| 伊阿宋 | 👑 赫拉 JP |
| 美狄亞 | MAJOR（100 × bet） |
| 奧菲斯 | MINOR（25 × bet） |
| 阿塔蘭忒 | MINI（10 × bet） |

**結算**：該整列合成為一個 **1×5 合成格**（`isHeroRow`）。

> **1×5 不是 wild**（企劃 2026-08-14 確認）。合成後它就是**一個全新的圖示**：
> 不替代任何顏色、不與任何符號連線、不進 Ways、不給分。
> 「給分」指的是 JP／MINI／MINOR／MAJOR 這個獎項本身，不是靠這一列去湊連線。

獎項排入 `heroRowPending`，等**本局連爆全部結束後**才發（與 v3 的 JP 同一個時機，
避免報獎蓋掉連爆演繹）。合成狀態一直留在盤面上（永遠不會 isMatched，所以不會被消除），
其他列照常連爆，下一次 spin 重鋪盤面時才消失。

角色列**不動 `splitCount`、也不寫進 `synthesizedColors`** —— 它是給分／發獎事件，
不是一次合成。分裂的來源只有一般合成（第一刀）與進階合成（第二刀）。

五個實作細節：

1. 偵測掛在 `STATE.SYNTHESIS` 的初始化，且排在一般合成掃描**之前**——
   否則那一列會先被當成一般合成候選。角色列不可能含船頭船尾，與船的偵測互不干擾。
2. 一次只處理由上往下第一個成立的列；合成後那一列不再是角色列，不會重複計。
3. 合成格「代表哪幾色」原本是 `[colorId, colorId2]` 硬組的。改成統一問
   `mergeColorIds(cell)`，它對帶 `isHeroRow` 的格**回空陣列** ——
   `calcWin()` 的兩處 `includes()` 因此都不會命中，整列在計分上等於不存在。
4. `computeCurrentWays()`（畫面左側的 WAYS 數字）**也必須另外擋一次**，讓角色列只算
   中性的 1。它走的是 `cell.colorId` 而不是 `mergeColorIds()`，所以 (3) 擋不到它 ——
   漏掉的話會出現「WAYS 顯示 7776、實際只賠 1024」這種兩邊對不上的狀況（單元測試
   `hero.noWaysContribution` 就是在守這個）。
5. 格子上仍留著 `colorId`／`colorIds`，那是給 `drawHeroRowCell()` 畫五色漸層用的，
   **不可拿來計分**。

## 四、出牌規則

- **五色合成率相等**：五色同權重，角色 7／武器 12（NG 另加船頭船尾各 2）。
- **第 3 輪單獨配重**（`V4_REEL3_CHAR_W`）：第 3 輪正好是角色列的中位格，
  在該欄把角色權重改成 海克力斯 3／伊阿宋 4／美狄亞 7／奧菲斯 9／阿塔蘭忒 13，
  做出「宙斯 < 赫拉 < MAJOR < MINOR < MINI」的五階獎頻率階梯。
  其他四輪維持等權，所以「五色合成率相等」不受影響（合成看的是同列相鄰兩格，不是單一輪）。
- `randomSymId()` / `randomReelSymId()` / `randomNormalSymId()` 都多收一個 `col` 參數；
  補牌（`applyGravity`）與初始鋪盤都要把欄號傳進去，否則第 3 輪的配重不會生效。

## 五、NG：地圖整段移除

`hasMapQuest()`（＝`!isV4()`）是總開關，擋掉 `drawMapPanel` / `drawMapShip` / `drawTMAnim` /
`tryAdvanceQuest` / `requestQuestAdvance` 的入列。盤面倍數恆 1，得分公式維持
`押注額 × 賠率 × Ways`。

盤面改為置中放大：`V4_LAYOUT_NG` grid x310 y124、格子 132（660×528）。
y 不能再往上：上方石像組下緣在 y=120；下緣也不能超過 spin 按鈕（y≈658）。

石像（`drawGodStatues`）在 v4 保留——它是兩尊神 JP 的顯示位置——但牌子下方的
v3 收集羅盤換成「角色列中心＝海克力斯／伊阿宋」的條件提示（v4 沒有累積過程）。

## 六、FG 航海地圖

新機制，與 v1～v3 的關卡地圖無關（另一組函式 `drawV4Voyage` 等）。
規則來自企劃 2026-08-13，呈現來自 2026-08-14 的美術需求。

**共 6 站**，倍數 ×1／×2／×3／×4／×5／×10。

- `v4VoyageStep` ＝ 船目前所在的站（0-based）。本次連爆得分套「船現在這一站」的倍數，
  **給完分船才前進 1 站** —— 所以第 1 次得分 ×1、第 2 次 ×2 …… 第 6 次 ×10。
- 船到第 6 站後不再前進，**本局後續連爆一律維持 ×10**。
- 站點狀態：`index <= v4VoyageStep` ＝ 已通過（彩色＋插旗）；其餘壓黑。**沒有雲霧遮罩**（見下）。
- **FG 每局重置**回起點；**SFG 不重置**，船位與倍數跨局保留。
- JP 與角色列彩金**不**與這個倍數相乘。

### 演繹（全部與連爆並行，不擋結算流程）

美術需求明訂「與盤面連爆並行，不打斷節奏」，所以 `v4VoyageAdvance()` 只是啟動動畫，
倍數當下就生效，**不等動畫播完**（這點與 v3 的羅盤不同 —— 那邊會等 `beaconAnim`）。
所有計時器由 `updateV4Voyage()` 每幀推進。

| 演繹 | 觸發 | 做法 |
|---|---|---|
| 船待機 | 平時 | 隨海浪上下晃＋輕微搖擺（sin LOOP） |
| 船移動 | 每段連爆得分 | 前半：原地彈起並淡出；後半：下一站淡入落下＋水花粒子 |
| 插旗 | 船抵達站點（動畫過半時） | 站點由壓黑轉彩色，`drawMapFlag()` 淡入小旗（沿用既有樣式） |
| 金羊毛終點 | 抵達第 6 站 | 聖林＋金羊毛亮起，全圖金光（`v4FleeceAnim`，時長為插旗的兩倍） |

### 與美術需求不同的兩個地方

1. **不做雲霧遮罩**（企劃 2026-08-14 決定）。
   美術需求原本寫「未通過站點之雲霧遮罩，沿用既有樣式」，實作後發現它與同一份需求裡的
   「未通過站點壓黑」互相打架 —— 藏寶圖那片霧濃度 0.99 幾乎全遮，壓黑的站點會被一起吃掉，
   玩家看不到上面還有幾站、終點是金羊毛。中間試過把濃度降到 0.66 讓站點以剪影透出來，
   最後企劃決定**整個拿掉**：未通過只用壓黑表示，整條航線一眼看得到終點。
   v1～v3 藏寶圖的 `drawMapFog()` 不受影響，那邊仍照舊。
2. **船停靠終點站時整體上移 20px**。聖林／金羊毛佔掉了站點本身的位置，
   船停在同一點會疊成一團；上移後看起來像停在聖林前的岸邊。

### NG 期間

美術需求寫「不顯示（或壓黑待機，待與美術討論）」。**目前採「不顯示」**，
因為 v4 的 NG 盤面是置中放大的，右側沒有留位置給面板（見 §六之二）。
若之後決定要壓黑待機，NG 版面得改回 FG 那組座標，盤面就不能置中放大了 —— 這兩件事互斥。

### 作廢的舊需求

美術需求載明「原『JP 小島／羅盤／小船』需求全數作廢」。那些是 v2／v3 的東西，
v4 本來就不會用到；**程式碼保留不刪**，因為 v1～v3 仍要能切回去對照。

## 六之二、v4 的版面（2026-08-14 依實截重排）

`syncV4Layout()` 在 `update()` 每幀檢查模式，**只在 NG↔FG 真的切換時**套用一次
（每幀都套會蓋掉調校面板「佈局」分頁的手動拖動）。它一次搬五個 LAYOUT 鍵：
`grid`／`mapPanel`／`statueL`／`statueR`／`fgCounter`。

| | NG | FG／SFG |
|---|---|---|
| 格子 | 132（盤面 660×528） | 130（盤面 650×520） |
| 盤面 | x310 y124（置中，中心 640） | x230 y120（中心 555） |
| 航海地圖 | 不畫 | x910 y120 245×520（貼盤面右緣，間距 30，同高） |
| 石像 L／R | x288／x681 | x203／x596 |
| FG 局數徽章 | （不畫） | x162 y375 |

四個硬條件：

1. 盤面 y 至少 122（石像組下緣 ≈120），下緣不能超過 spin 按鈕（y≈658）。
2. 盤面左邊要留得下 **WAYS 欄位**（錨在盤面上：中心＝`GRID_X-68`、寬 110）
   與 **FG 局數徽章**（`fgCounter.x` 是**中心**）。兩者要對齊同一直行、上下錯開。
3. 航海地圖**貼著**盤面右緣。
4. 石像組對齊盤面中心：組跨距固定 704、兩者間距固定 393 ⇒ `statueL.x = 盤面中心 − 352`。

註：左側原本的 JP 獎池面板與連線紀錄面板（`drawJPPanel`／`drawWinLog`）**已是死程式**，
沒有被 `draw()` 呼叫，所以左邊整條是空的，可以給 WAYS／局數徽章用。

**三個踩過的坑（都是截圖驗證抓到的，單元測試守不到）**：

- `applyRuleLayout()` 直接覆寫 `LAYOUT.grid` 與 `CELL_SIZE` 卻沒清掉 `_v4LayoutMode`，
  於是「在 FG 中切換規則版本」之後 `syncV4Layout()` 誤判模式沒變、不把 FG 版面補回來。
  修法：`applyRuleLayout()` 裡把 `_v4LayoutMode` 設回 null。
- **`fgCounter` 沿用 v3 的 x=190 會壓在盤面上**。那個值是配 `DEFAULT_LAYOUT` 的盤面
  x=258 調的，搬到 v4 FG 的盤面（原本 x=195）就重疊了。改成跟著盤面走。
- **航海地圖沿用 v3 的 x=1010 離盤面 165px**，看起來像兩塊沒關係的東西。改成貼齊。

教訓：新版本沿用舊版本的 LAYOUT 座標時，要把**每一個**跟盤面有相對關係的元件重算一次
（WAYS／局數徽章／石像／面板），不能只搬 `grid`。

## 十二、五角連線聽牌提示（企劃 2026-08-19）

上方兩塊彩金牌下方一排 **5 個圓圈**，對應 5 個輪。目的是把「還差幾個」可視化。

- **觸發**：某一列湊到 `V4_HINT_MIN`（＝3）個以上、**互不相同**的角色。
  重複角色不算進度（同一隻出現兩次湊不成五角連線）；已合成的格不計入；
  已經湊滿 5 個的交給 `findHeroRow()`，不算聽牌。
- **呈現**：有角色的輪填入該角色圖示（裁成圓形）＋該色底與呼吸光；缺的輪是虛線空槽。
  只缺 1 個（`nearMiss`）時光暈與外框加強。
- **定獎預告**：中位（第 3 輪）已有角色時，同步亮起對應獎項 ——
  海克力斯→宙斯石像、伊阿宋→赫拉石像（走 `drawGodStatues` 原本的 `chosen` 呼吸光路徑），
  美狄亞／奧菲斯／阿塔蘭忒→三階彩金列對應那一格。中位是空槽時不亮任何獎項。
- **多列輪播**：淡入淡出，每列停留 `V4_HINT_HOLD`（2.2s）、淡入淡出 `V4_HINT_FADE`（0.35s）。
  單列時不輪播、alpha 恆 1。清單內容一變（換盤／補牌）就從第一筆重新開始，
  避免索引指到已不存在的列。
- **滾動中不顯示**：`v4BoardSettled()` 要求每一格 `reelState === 'done'`，否則會提前洩題。

### 待調

`V4_HINT_MIN = 3` 是照企劃「3 個以上」設的。NG 角色出現率約 35%／格，
一列湊到 3 個不同角色並不罕見，實測常有 2~4 列同時符合、輪播會一直在動。
若覺得太吵，把這個常數改成 4（只在「差一個」時才提示）即可。
